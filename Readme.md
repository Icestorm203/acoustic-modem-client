# 🖥 Acoustic Modem Client — консольный клиент для работы с акустическим модемом (C++, Winsock2)

Acoustic Modem Client — учебный консольный клиент на C++ (MSVC + Winsock2), который подключается к акустическому модему по TCP и реализует два режима работы: RAW и DACAP.
Клиент поддерживает запуск нескольких узлов из одного исполняемого файла, обмен сообщениями, протокол RTS/CTS/DATA и логирование в отдельные файлы.

Проект создан как учебный пример работы с сетевыми API Windows, потоками, обработкой данных и реализацией простого сетевого протокола.

## 📌 Требования

Для запуска проекта необходимы:
- Windows 10 / 11
- MSVC toolchain (cl.exe)
- Cursor IDE или Visual Studio 2022
- Winsock2 (входит в Windows SDK)
- Акустический модем или тестовый TCP‑сервер по адресу: 10.78.1.1:9200

## 🚀 Возможности
- Один исполняемый файл `Client.exe`
- Запуск нескольких узлов, например:
```
Client.exe --id 1
Client.exe --id 2 --mode dacap
Client.exe --id 3 --mode raw
```
- Гибридный выбор режима:
- Если `--mode` указан → используется он
- Если не указан → программа спрашивает режим в консоли
- Уникальные логи по id, например:
- log_1.txt
- log_2.txt
- log_3.txt

- Поддержка протокола DACAP:
	- RTS → CTS → DATA
	- backoff при чужом RTS
	- оценка расстояния по RTT
- Поток приёма RECVIM
- Winsock2 TCP‑клиент

## ▶️ Запуск проекта

### **Вариант 1 — через Visual Studio**
1. Открыть Client.sln
2. Выбрать конфигурацию:
- Configuration: Debug / Release
- Platform: x64 или Win32
3. Нажать Start (F5)

Исполняемый файл появится в папке:
```
build/x64/Debug/Client.exe
```
или
```
build/x64/Release/Client.exe
```

### **Вариант 2 — через VS Code/Cursor IDE / терминал**

1. Перейти в папку проекта:
```
cd acoustic-modem-client
```
2. Убедиться, что MSBuild доступен.

Проверка в терминале:
```
msbuild -version
```
Должно показать версию MSBuild.
3. Собрать:
```
msbuild Client.sln
```
4. Запустить и написать id, например:
```
.\build\x64\Debug\Client.exe --id 1
```

## 🏁 Запуск узлов

Клиент поддерживает запуск нескольких узлов из одного EXE.

Пример запуска трёх узлов в разных консолях:

### **Узел 1 — режим спрашивается в консоли**
```

```
### **Узел 2 — режим DACAP заранее**
```
Client.exe --id 2 --mode dacap
```
### **Узел 3 — режим RAW заранее**
```
Client.exe --id 3 --mode raw
```

## 📡 Работа клиента

После запуска клиент спрашивает:
```
Enter dest addr:
Ack? (ack/noack):
Data:
```

Пример отправки:
```
Enter dest addr: 2
Ack? (ack/noack): ack
Data: test
```
Если модем доступен, узлы обмениваются пакетами RAW или DACAP.

## 💾 Логи
Каждый узел пишет свой лог в отдельный файл:

log_<id>.txt

Пример:

- log_1.txt
- log_2.txt
- log_3.txt

В логах фиксируются:
- SEND / RECV события
- тип команды (RTS / CTS / DATA)
- задержка
- попытки
- размер пакета
- PDR

## 🧩 Архитектура и ключевые компоненты

### ** Основной поток**
- подключение к модему
- ввод параметров отправки
- формирование пакетов RAW/DACAP
- отправка через Winsock2
- логирование
- расчёт PDR и задержки

### ** Поток приёма (receiver)**
- чтение RECVIM
- разбор пакетов
- обработка DACAP (RTS/CTS/DATA)
- вызов handleProtocol

### ** DACAP‑логика**
- сериализация/десериализация пакетов
- расчёт RTT
- оценка расстояния
- вычисление backoff
- автоматическая отправка CTS и DATA

### ** 🔌 Поток данных (DACAP)**
- Узел отправляет RTS
- Получатель отвечает CTS
- Узел отправляет DATA
- RTT используется для оценки расстояния
- При конфликте узлы ждут backoff

- сериализация протокола
